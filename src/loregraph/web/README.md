# LoreGraph web

- **`landing/`** — the static **GitHub Pages** site (this is the product). Self-contained: React via CDN + plain CSS + JSX. The editable source runs with in-browser Babel; `build-landing.cjs` precompiles it into a production bundle.
- **FastAPI backend** (`server.py`, `routes/`, `schemas.py`) — an optional local query API, launched by `loregraph view`. Not part of the public static site.

## Preview locally

```bash
node serve-landing.cjs            # → http://localhost:4178 (source, Babel-in-browser)
```

## Build + publish

Live site: **https://loregraph.ungetsu.net**

```bash
cd src/loregraph/web
npm install        # first time on a machine (esbuild + gh-pages)
npm run deploy     # build landing/ → dist/ (precompiled, prod React), then push to gh-pages
```

`npm run deploy` works from any fresh clone — `build-landing.cjs` builds, [`gh-pages`](https://www.npmjs.com/package/gh-pages) publishes via the repo's `origin` remote, so there's no branch or worktree to set up by hand.

> **Data.** The site reads pre-computed graphs from `landing/data-exports.js`, generated by `scripts/build_frontend_data.py` from `data/exports/*.json`. If the exports changed, regenerate it before `npm run deploy`.

> **`landing/CNAME` is load-bearing.** `npm run deploy` empties the `gh-pages`
> branch before publishing, so anything the live site needs has to be produced by
> the build. A CNAME that exists only on that branch is deleted by the next
> deploy, and GitHub reads its absence as "no custom domain" and drops the domain
> from the repo's Pages settings — which takes the site off
> `loregraph.ungetsu.net` until someone puts it back.

### The Cloudflare route

[`wrangler.jsonc`](../../../wrangler.jsonc) at the repo root configures a Worker
named `loregraph` that serves `dist/` as static assets, building it with the same
`build-landing.cjs`. Nothing about the site changes — it is static either way, so
this is only a question of who holds the files.

Cloudflare Workers Builds runs from the repo, so a push is the whole deploy; the
manual `npm run deploy` above exists because GitHub Pages is fed by a branch that
nothing automated writes to.

Two things live outside the repo and have to be done in the Cloudflare dashboard:
point `loregraph.ungetsu.net` at the Worker as a custom domain, and remove it from
the repo's Pages settings. Do it in that order — the domain answers from one place
at a time, and Pages holds it today.

### Cross-device workflow

1. `git clone git@github.com:YunyueLi/LoreGraph.git`
2. `cd LoreGraph/src/loregraph/web && npm install`
3. edit files under `./landing/`, then `npm run deploy`
